# Bone Care｜把骨折挡在门外

**骨质疏松与家庭骨健康知识平台**

这是一个用于骨质疏松宣传与家庭健康知识传播的静态网站。主要任务只有三件事：让更多人知道骨质疏松风险，知道什么时候应该进入专业评估，回家以后知道怎么长期管理。

## 当前阶段

当前处于持续完善、专业审核与实践准备阶段。网站展示的部分工具仍可能是候选稿或内部审核版本。本项目不宣称已经形成成熟临床模式，也不宣称已经证明能够降低骨折发生率、改善骨密度，或已在不同机构完成有效性验证。

## 网站

GitHub Pages 地址：`https://sibaraleo-spec.github.io/bone-care/`。第一版使用仓库子路径，所有页面采用相对路径，因此可以在 GitHub Pages 子路径下直接工作。

## 本地预览

网站是纯静态文件，不需要数据库、登录、评论系统或追踪器。进入 `dist/` 后使用任意静态服务器预览，例如：

```bash
cd dist
python3 -m http.server 8000
```

然后访问 `http://localhost:8000/`。

## 目录结构

```text
dist/                    # GitHub Pages 与 Sites 的发布目录
  index.html             # 首页
  about.html             # 关于实践
  resources.html         # 公开资料分类
  changelog.html         # 更新日志
  404.html               # 找不到页面
  assets/                # 样式、脚本、图像与 favicon
resources/               # 后续正式公开资料的预留目录
docs/                    # 项目边界与维护说明
.github/workflows/       # GitHub Pages 自动部署
```

## 内容更新

1. 先确认内容属于首页、关于实践、公开资料或更新日志中的哪一页。
2. 只修改 `dist/` 内对应页面和资源；新增正式公开文件时放进 `resources/`，并在 `resources.html` 中明确状态。
3. 不要把候选稿写成“已审核”，不要创建尚未存在的下载链接。
4. 每次真实完成的工具或网站变化，都在 `changelog.html` 中记录版本和日期。
5. 提交前检查页面内部链接、手机布局、图片加载和医学边界。

## GitHub Pages 部署

仓库使用 `.github/workflows/pages.yml`，推送到 `main` 后自动上传 `dist/` 并发布。首次创建仓库后，在 GitHub 的 **Settings → Pages** 确认 Source 使用 **GitHub Actions**；如果工作流已运行，Pages 会自动完成后续部署。

## 医学与隐私边界

本网站内容主要用于健康教育、项目交流与实践讨论，不替代医生面对具体患者作出的个体化诊断、治疗和急救判断。涉及临床流程、随访规则和专业工具的内容，正式应用前应完成相应专业审核并结合所在医疗机构规范执行。

不得上传或展示可识别的患者个人资料、真实病历、身份证号、手机号、住址或未脱敏医疗数据。

## 如何提出建议

欢迎通过 GitHub Issue 提出页面可读性、工具边界、资料分类或协作流程建议。请勿在 Issue 中提交患者信息、病历、联系方式或其他敏感医疗数据。
